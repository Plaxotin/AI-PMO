## 1. Функциональные требования

### FR-1. Отказ от кнопок
Все inline-клавиатуры удаляются из кода. Взаимодействие — только текстовые
команды. Многошаговые состояния (waiting_*) сохраняются только для подтверждения
создания поручения («да/нет»).

### FR-2. Каналы взаимодействия
- **Личный чат** — полный функционал (см. FR-3, FR-6).
- **Общий чат** — только через упоминание `@Plaxotin_task_bot`, три команды (FR-4).

### FR-3. Контроль доступа (личка)
- **Две роли:**
  - **Суперадминистратор** — только `@plaxotin`. Любые изменения, включая
    конфигурацию бота (список админов, лимиты антифлуда, расписание дайджеста).
  - **Администратор** — любые изменения в реестре поручений (Google Sheets),
    но **запрет на изменение конфигурации**.
- Белые списки в `.credentials/config.json`: `"superadmin": "plaxotin"`,
  `"admins": [...]` (username без @, регистронезависимо).
- Личные сообщения от пользователей не из списков — молча игнорируются + запись в лог.
- Управление списком админов (`добавить админа @user` / `убрать админа @user` /
  `админы`) — **только суперадминистратор**.

### FR-4. Команды в общем чате (для всех участников)
| Команда | Синтаксис | Кто может |
|---|---|---|
| Показать поручения | `@bot мои поручения` / `@bot все поручения` / `@bot поручения <проект>` / `@bot поручения статус <статус>` | все |
| Закрыть поручение | `@bot закрыть #12` | все, но только **своё** (проверка по user_mapping) |
| Создать поручение | `@bot создать поручение: Проект=…; Описание=…; Ответственный=…; Срок=…` | все |

Создание: все 4 поля обязательны (Проект, Описание, Ответственный, Срок);
Автор — из Telegram-аккаунта автоматически; Статус — «Новое».
Перед записью бот присылает эхо с распарсенными полями и ждёт текстовое
подтверждение «да» (иначе — отмена, таймаут 60 с).

### FR-5. Антифлуд
- Токен-бакет на пользователя: **10 команд/мин, 100 команд/день** в группах.
- Админы: **1000 команд/день**.
- Глобальный потолок: **500 команд/день** на бота.
- Превышение → молчаливый игнор до конца окна; первое срабатывание — одно предупреждение.
- Счётчики в памяти процесса (переезд в SQLite — при росте нагрузки).

### FR-6. Админские команды (только личка)
Доступны **администраторам и суперадминистратору** (изменения в реестре):
| Команда | Синтаксис |
|---|---|
| Изменить срок | `срок #12 20.08.2026` |
| Сменить статус | `статус #12 В работе` |
| Сменить ответственного | `ответственный #12 Иванова Т.` |
| Изменить описание | `описание #12 новый текст` |
| Добавить комментарий | `комментарий #12 текст` |
| Удалить поручение | `удалить #12` (+ подтверждение «да») |
| Дайджест дедлайнов вручную | `дайджест` |

Только **суперадминистратор** (изменения конфигурации):
| Команда | Синтаксис |
|---|---|
| Управление админами | `добавить админа @user` / `убрать админа @user` / `админы` |
| Лимиты антифлуда | `лимиты <в-минуту> <в-день>` |
| Версии конфигурации | `версии` / `откатить конфиг <версия>` |

### FR-7. Уведомления администраторам
- **Только дайджест изменений реестра один раз в конце дня** (например, 20:47 МСК):
  что создано/закрыто/изменено за день, кем, с номерами поручений.
- **Если изменений не было — уведомление не отправляется.**
- Мгновенные уведомления админу о каждом действии (текущее поведение) — отключаются.
- Получатели дайджеста: суперадминистратор + все администраторы (личка).

4. **Даты** — принимать `завтра`, `послезавтра`, `в пятницу`, `20.08`, `20.08.2026`;

5. **Защита от дублей** — при создании проверять «проект + описание» за последние 10 минут.
6. **Аудит-лог** — лист «Лог» в той же таблице: дата, Telegram user, действие, ID, детали.

8. **Дайджест дедлайнов по расписанию** — systemd timer, будни 9:17 МСК, в общий чат.

## 4.1. Почему я предлагаю ядро без LLM — без технических терминов

Представьте два способа, как бот может понимать ваши слова:

**Способ 1. «Разговорник» (моё предложение для ядра).**
У бота есть точный список фраз, которые он знает наизусть: «закрыть #12»,
«мои поручения», «срок #12 20.08.2026». Как фразеология в автоматической
кассе: пока вы говорите по шаблону — работает мгновенно, бесплатно и без ошибок.

**Способ 2. «Живой переводчик» (LLM, как в RACI-боте).**
Бот отправляет каждую фразу в нейросеть, та «читает» смысл. Понимает любые
формулировки («закрой пожалуйста двенадцатую задачку»), но: каждый запрос
стоит токены, ответ приходит 3–10 секунд, и нейросеть иногда понимает
неправильно — а ошибка в реестре поручений опаснее, чем ошибка в RACI-матрице.

Примеры:

| Фраза пользователя | Разговорник | LLM |
|---|---|---|
| `@bot закрыть #12` | ✅ мгновенно, бесплатно | ✅ за токены, 5 сек |
| `@bot мои поручения` | ✅ мгновенно | ✅ за токены |
| `@bot закрой двенадцатое` | ❌ не понял, подскажет формат | ✅ понял |
| `@bot ну закрой уже это` | ❌ не понял | ⚠️ догадается, но может ошибиться с номером |

Моя рекомендация — **гибрид**: сначала «разговорник» (покрывает 90% команд
бесплатно и мгновенно), а если фраза не распознана — бот честно отвечает
«Не понял, вот список команд» вместо того, чтобы гадать нейросетью.
LLM можно подключить позже отдельным режимом для тех, кто не любит шаблоны, —
и тогда антифлуд (FR-5) как раз ограничит расход токенов.

## 7. Изменения v2.1 (08.08.2026)

Утверждённая владельцем переработка UX поверх v2.0.

### 7.1. Новая модель взаимодействия

- **Групповой чат: бот не реагирует на сообщения вообще.** Разбор упоминаний
  и групповые команды удалены. Группа (chat_id из telegram.json) получает
  только автоматические рассылки:
  - утренний дайджест дедлайнов (check-deadlines, как раньше);
  - вечерний дайджест изменений (20:47 МСК, только если были изменения).
    Получатель перенесён из личек админов в общий чат (fallback — лички админов).
- **Личка — для всех пользователей.** Молчаливый игнор неавторизованных
  отменён. Возвращены минимальные inline-кнопки:
  - любое сообщение или /start → приветствие + кнопки «📋 Мои поручения»
    и «✅ Закрыть поручение»;
  - список открытых поручений — по кнопке на поручение («✅ #N описание»,
    callback `close:<id>`), внизу кнопка «🔄 Обновить»;
  - закрытие в один тап (статус → Выполнено), только своё: проверка
    владельца по user_mapping.json выполняется и на callback (защита
    от подделки callback_data);
  - username не найден в user_mapping → «Вы не найдены в реестре,
    обратитесь к администратору».
- **Админы и суперадмин** в личке: те же кнопки + все текстовые команды v2.0.
  Создание поручений стало админской командой (пользователи просят админов).
  Суперадмин: команды конфигурации без изменений.

### 7.2. Новые команды

- `новый реестр <название>` (админы и суперадмин): создаёт новую
  Google-таблицу со стандартными заголовками реестра, делится ею с
  `owner_email` из config.json (writer, без уведомления; если ключ пуст —
  предупреждение, что доступ нужно выдать вручную), переключает
  `spreadsheet_id` на новый (прежний сохраняется как `prev_spreadsheet_id`),
  сбрасывает кэш, пишет действие `new_registry` в аудит-лог, отвечает ссылкой.
- `реестр` — ссылка на текущую таблицу; доступна всем в личке.

### 7.3. Ссылка на реестр

Футер `📋 Реестр: https://docs.google.com/spreadsheets/d/<id>/edit`
добавляется в дайджесты, списки поручений и подтверждения создания/закрытия.

### 7.4. Что сохранено без изменений

Роли (superadmin + admins), антифлуд (токен-бакет, распространён и на
нажатия кнопок), вечерний дайджест 20:47 МСК только при наличии изменений,
аудит-лог «Лог» (закрытие кнопкой логируется с пометкой `[кнопка]`),
кэш чтения TTL 60 с, умные даты, защита от дублей, версии и откат конфига,
команда `дайджест`.

### 8.1. owner_email

### 8.2. Утренний дайджест дедлайнов (systemd timer)
`plaxotin-task-digest.timer` + oneshot-сервис `plaxotin-task-digest.service`:
будни 9:17 МСК (OnCalendar=Mon..Fri 06:17 UTC, сервер в UTC) запускается

в общий чат из telegram.json. Вечерний дайджест изменений (20:47 МСК)
работает как в v2.1.

### 8.3. Короткое приветствие админа
Для админа/суперадмина приветствие в личке сокращено до компактного
раздела «Вот что я умею:» со списком команд (без блоков про конфигурацию)
с финальной фразой: «💬 А ещё вы можете написать мне любую задачу по
изменению реестра поручений в свободной форме — я пойму и предложу
подтверждение.» Приветствие обычных пользователей (с кнопками) не менялось.

### 8.4. LLM-режим свободной формы (только админы/суперадмин, только личка)
Если текст админа не распознан парсером:
1. Текст уходит в Kimi (Moonshot, OpenAI-совместимый API,
   base_url https://api.moonshot.ai/v1, model moonshot-v1-8k; ключ —
   `.credentials/kimi.json`, chmod 600, не коммитится). Модуль
   `scripts/llm.py`, реализация на requests.
2. Модель переводит просьбу в каноническую команду бота и возвращает
   строго JSON `{"command_text": "<команда>"}` или `{"command_text": null}`;
   в системном промпте передаётся текущая дата для относительных дат.
3. Бот показывает интерпретацию («🤖 Понял так: …») и ждёт «да» (60 с)
   через стандартный механизм подтверждений. «да» → исполнение через
   обычный путь (commands.parse → dispatch): все проверки прав, аудит,
   инвалидация кэша. Иначе — отмена.
4. Kimi недоступен или вернул null → стандартное «Не понял команду.
   Вот что я умею: …».
5. LLM-вызов учитывается в антифлуде как обычная команда.
   Таймаут вызова 60 с, max_tokens 1000, temperature 0.1.

Обычные пользователи LLM-режим не вызывают: их нераспознанный текст
по-прежнему ведёт на приветствие с кнопками.
