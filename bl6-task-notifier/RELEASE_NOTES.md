# BL-6 «Администратор поручений» — Release Notes

## v1.0 — 08.08.2026

**Состояние:** бот @Plaxotin_task_bot с inline-кнопками, задеплоен на Timeweb.

Починено при переносе на сервер:
- Установлены gspread/google-auth в venv (кнопки не работали: реестр не читался)
- Фикс гонки таймаутов long polling (read timeout = poll + 15 с; спам «Read timed out» устранён)
- State-машина: ключ `chat_id:user_id` (в группе состояния не пересекаются)
- Упоминание бота срезается из текста команд; валидация числового ID поручения
- Личка отвечает без упоминания

Известные ограничения: inline-кнопки, нет ролей, нет антифлуда, мгновенные
уведомления админу о каждом действии, сервис под root.

## v2.0 — 08.08.2026

По спеке SPEC_BL6_v2.md. Автор: Kimi Work (реализация), владелец: @plaxotin.

Сделано:
- Полный отказ от inline-кнопок: взаимодействие только текстовыми командами;
  многошаговые состояния остались только для подтверждения «да/отмена»
  (создание и удаление поручения, таймаут 60 с, состояние per user).
- Новый модуль `scripts/commands.py` — чистый парсер команд без сети
  (regex/ключевые слова, без LLM). Нераспознанное → «Не понял команду» + справка.
- `scripts/test_commands.py` — 54 юнит-теста парсера (все команды, регистр,
  лишние пробелы, умные даты, ошибки формата). Все зелёные.
- Роли: superadmin = @plaxotin (всё + конфигурация), admins из config.json
  (изменения реестра). Личка от посторонних — молчаливый игнор + лог.
  В группе — только через упоминание @Plaxotin_task_bot.
- Групповые команды: мои/все поручения, поручения <проект>, поручения статус
  <статус>, закрыть #N (только своё, проверка по user_mapping.json),
  создать поручение (4 обязательных поля, эхо-просмотр + «да»).
- Админские (личка): срок/статус/ответственный/описание/комментарий #N,
  удалить #N (с подтверждением), дайджест.
- Суперадмин: добавить/убрать админа, админы, лимиты <мин> <день>,
  версии, откатить конфиг <версия> (копия снапшота + systemctl restart).
- Антифлуд (в памяти процесса): 10 команд/мин и 100/день в группах,
  1000/день админам, глобально 500/день. Первое превышение — одно
  предупреждение, дальше молчаливый игнор до конца окна.
- Аудит-лог: лист «Лог» в той же Google-таблице (создаётся через API,
  если нет). Пишутся все мутации (create/close/update/delete).
- Вечерний дайджест изменений админам в личку в 20:47 МСК (сервер в UTC);
  если изменений за день нет — не отправляется. Мгновенные уведомления
  админу (notify_admin) удалены полностью.
- Кэш чтения реестра: TTL 60 с, инвалидация при любой записи.
- Умные даты: завтра/послезавтра/сегодня, «в <день недели>», ДД.ММ,
  ДД.ММ.ГГГГ → нормализация в ДД.ММ.ГГГГ.
- Защита от дублей: совпадение «проект+описание» за последние 10 минут
  (по аудит-логу) → отказ с пояснением.
- task_manager.py: обратносовместимое расширение update — новые флаги
  --assignee и --description (столбцы F и E); остальная логика не менялась.
- Версионирование: снапшот versions/v2.0/ (scripts + requirements.txt +
  RELEASE_NOTES.md + config.json + user_mapping.json, chmod go-rwx),
  versions/CURRENT → v2.0.

Известные ограничения: счётчики антифлуда в памяти (сбрасываются при
рестарте), сервис по-прежнему под root (переезд — отдельной задачей),
дайджест уходит только админам, которые хоть раз написали боту в личку
(chat_id сохраняется в .credentials/admin_chats.json).

## v2.1 — 08.08.2026

Переработка UX (утверждена владельцем). Автор: Kimi Work.

Сделано:
- **Групповой чат: бот полностью молчит.** Убран разбор упоминаний и все
  групповые команды. Группа (chat_id из telegram.json) получает только
  автоматические рассылки: утренний дайджест дедлайнов (check-deadlines)
  и вечерний дайджест изменений (20:47 МСК, только при наличии изменений;
  получатель сменился с личек админов на общий чат, fallback — лички админов).
- **Личка — для всех пользователей, с inline-кнопками** (кнопки возвращены,
  минимальный набор):
  - Обычный пользователь: любое сообщение или /start → приветствие + кнопки
    «📋 Мои поручения» и «✅ Закрыть поручение». Список открытых поручений —
    по inline-кнопке на поручение («✅ #N описание», callback close:<id>),
    внизу «🔄 Обновить». Закрытие в один тап (status=Выполнено).
  - Проверка владельца на callback close:<id> по user_mapping.json —
    защита от подделки callback_data; попытка закрыть чужое логируется.
  - username не в user_mapping → «Вы не найдены в реестре, обратитесь
    к администратору».
  - Молчаливого игнора в личке больше нет.
  - Админы/суперадмин: те же кнопки + все текстовые команды v2.0
    (создание поручения теперь админское; пользователи создают через админов).
- **Новая команда `новый реестр <название>`** (админы и суперадмин): создаёт
  Google-таблицу со стандартными заголовками, делится с owner_email из
  config.json (writer, без уведомления; если не задан — предупреждение),
  переключает spreadsheet_id (старый → prev_spreadsheet_id), сбрасывает кэш,
  пишет в аудит (действие new_registry), отвечает ссылкой.
- **Команда `реестр`** — ссылка на текущую таблицу, доступна всем в личке.
- **Футер со ссылкой на реестр** в дайджестах, списках поручений и
  подтверждениях создания/закрытия.
- Антифлуд распространён и на нажатия кнопок (callback).

Сохранено из v2.0: роли, токен-бакет (10/мин, 100/день, 1000/день админы,
500/день глобально), аудит-лог «Лог» (закрытие кнопкой логируется с пометкой
[кнопка]), кэш TTL 60 с, умные даты, защита от дублей, версии/откат,
подтверждение «да» для создания/удаления.

Тесты: 67 юнит-тестов парсера (test_commands.py) — все зелёные.
Права по ролям, «новый реестр», «реестр», умные даты, ошибки формата.

Известные ограничения: owner_email в config.json пока пустой (доступ к новым
реестрам выдавать вручную или заполнить ключ); счётчики антифлуда в памяти;
сервис под root.

## v2.2 — 08.08.2026

Четыре задачи владельца. Автор: Kimi Work.

Сделано:
- **owner_email = plaxotin9@gmail.com** в config.json — команда
  `новый реестр` теперь реально шарит новую таблицу на этот email
  (writer, без уведомления).
- **Утренний дайджест дедлайнов по расписанию**: systemd timer
  `plaxotin-task-digest.timer` (OnCalendar=Mon..Fri 06:17 UTC = 9:17 МСК)
  → oneshot-сервис запускает `task_manager.py check-deadlines`
  (сводка уходит в общий чат, как раньше). Вечерний дайджест изменений
  (20:47 МСК) не тронут.
- **Короткое приветствие для админов/суперадмина**: только компактный
  раздел «Вот что я умею:» + фраза про свободную форму. Приветствие
  обычных пользователей (с кнопками) не изменилось.
- **LLM-режим свободной формы** (только админы/суперадмин, только личка):
  нераспознанный парсером текст → Kimi (Moonshot, moonshot-v1-8k,
  OpenAI-совместимый API; новый модуль scripts/llm.py) переводит просьбу
  в каноническую команду → бот показывает интерпретацию и ждёт «да»
  (60 с) → исполнение через обычный путь commands.parse + dispatch
  (все проверки прав, аудит, кэш). Kimi недоступен/вернул null →
  стандартное «Не понял команду». Обычные пользователи LLM не вызывают.
  Таймаут 60 с, max_tokens 1000, temperature 0.1. LLM-вызов считается
  командой в антифлуде. Ключ — .credentials/kimi.json (chmod 600,
  не коммитится; локально только kimi.json.example).
- task_manager.py: флаг `list --json` (машиночитаемый вывод для smoke).

Тесты: 77 юнит-тестов (test_commands.py) — все зелёные, включая
маршрутизацию нераспознанного текста (админ → llm, пользователь →
fallback) и разбор ответа модели (extract_json, без сети).

Известные ограничения: прежние (антифлуд в памяти, сервис под root).

## v3.0 — 08.08.2026

Полный пивот UX: отказ от канонических команд для админов, inline-кнопки
для пользователей, LLM как основной интерфейс администрирования.
Автор: Kimi Work.

Сделано:
- **Групповой чат: бот полностью молчит** (v2.1 сохранено). Никаких
  упоминаний, никаких команд. Только автоматические рассылки.
- **Личка — единый экран с inline-кнопками для всех:**
  - «📋 Мои поручения» — список открытых задач с кнопками закрытия
  - «📂 Открыть реестр» — прямая ссылка на Google Sheet
  - «📋 Выбрать реестр» — переключение между несколькими реестрами
- **Админы/суперадмин: канонические команды полностью отключены.**
  Весь ввод идёт через LLM (scripts/llm.py): свободная форма →
  интерпретация → подтверждение «да» → исполнение через parse_canonical.
  Суперадмин дополнительно получает свободный чат с LLM на админские темы.
- **commands.py v3.0**: `parse()` — для user: help + просмотр/закрытие;
  для admin/superadmin: только help/registry_link, всё остальное → unknown
  → LLM. `parse_canonical()` — полный набор команд без проверки роли
  (для LLM-интерпретаций после подтверждения).
- **Поддержка нескольких реестров**: `cfg['registries']` — список с
  флагом `active`. Переключение через inline-кнопки или LLM-команду.
- **Приветствие с названием активного реестра** (для всех ролей).
- **Сохранено из v2.2**: роли, антифлуд, аудит-лог, кэш TTL 60 с,
  умные даты, защита от дублей, версии конфигурации, вечерний дайджест.

Известные ограничения: прежние + `cmd_new_registry` не добавляет новый
реестр в список `registries[]` (исправлено в v3.1).

## v3.1 — 13.08.2026 (текущая продовая версия)

Багфикс и доработка регистра реестров. Автор: Kimi Work.

Сделано:
- **Фикс `cmd_new_registry`**: новый реестр корректно добавляется в
  `cfg['registries']` с флагом `active=True`, все предыдущие реестры
  сбрасываются в `active=False`. Fallback `spreadsheet_id` обновляется
  для совместимости со старыми модулями. Кнопка «📋 Выбрать реестр»
  теперь показывает все реестры, переключение работает корректно.
- **Фикс `feedback.py`**: модуль сбора идей/багов (`/идея`, `/баг` из
  группового чата) теперь использует активный реестр из `cfg['registries']`
  (как `task_manager.py`), а не `spreadsheet_id` напрямую. Фидбек попадает
  в правильную таблицу после переключения реестра.
- **Добавлен сбор фидбека из группы**: `/идея` и `/баг` — единственное
  исключение из правила «в группе бот молчит». Записи идут во вкладку
  «Бэклог BL-6» с аудит-логом. Антифлуд работает на фидбек тоже.
- **Обновлены RELEASE_NOTES**: добавлены секции v3.0 и v3.1.

Известные ограничения: счётчики антифлуда в памяти (сбрасываются при
рестарте); сервис по-прежнему под root; дайджест уходит админам,
которые хоть раз написали боту в личку (chat_id сохраняется в
.credentials/admin_chats.json).
