# Verifier v16 — production P0

Предмет: миграция существующего plain-HTML воркспейса на поддерживаемый full-stack проект без редизайна. Лендинг и PNG должны остаться байт-в-байт прежними.

## Критерии

- [x] Отдельная точка отката демо: версия `6a3e03f` и файловая копия `rollback/step3/app-before`.
- [x] Постоянное серверное хранилище рисков, решений, поручений и событий в MySQL через Drizzle.
- [x] Аутентификация Kimi; владелец приложения (`admin`) получает роль РП, остальные пользователи — read-only участник.
- [x] Неавторизованный `pmo.state` → 401; mutation участника → 403; решение участника остаётся `wait`.
- [x] РП принимает `D-02` реальным кликом; `P-D-02` создаётся атомарно и связывается с решением и риском.
- [x] `decision.accepted` и `task.created` записаны с фактической атрибуцией пользователя.
- [x] Данные доступны в новом браузерном контексте и после холодного production-запуска.
- [x] Повторная обработка решения отклоняется с 409 и не создаёт дубль поручения.
- [x] Эталонная таблица решений сохранена; под ней добавлен раскрываемый серверный журнал.
- [x] Лендинг и `matreshka-full-cycle.png` не изменены; у лендинга остаются ровно два основных действия.
- [x] Desktop/mobile browser checks: нет JS errors, локальных 404 и горизонтального overflow на 390 px.
- [x] Production bundle запускается из каталога без `node_modules`; `Dockerfile` и `dist/boot.js` присутствуют.
- [x] Telegram / Email / MAX по-прежнему честно обозначены как неподключённые.

## Проверки

- `check_p0.py` — статические критерии и неизменность исходных активов.
- `browser_p0.py` — РП, участник, анонимный вход, реальное утверждение, persistence, mobile, лендинг.
- `production_smoke.py` — production bundle после холодного запуска.
- `api-results.json` — HTTP-результаты авторизации, запрета и повторной mutation.
- `browser-results.json`, `production-results.json` — машинные результаты браузерных прогонов.

Ограничение этапа: P0 переводит на сервер цепочку «риск → предложение → решение → поручение» для учебного проекта. Остальные демонстрационные инструменты и внешние каналы не объявляются production-интеграциями.
