## BL-6 «Task notifier» (@Plaxotin_task_bot) — статус: Реализовано (MVP), актуально на 10.09.2026

- Реестры поручений в Google Sheets; маппинг колонок по ИМЕНАМ заголовков
  (COLUMN_SYNONYMS дублируется в bot_handler.py и task_manager.py — держать синхронно).
  Поле «Контрагент» (синонимы Компания/КА), «Проект» упразднён. Срок: Srok korr приоритетнее Srok plan.
- Вкладка «Контакты» (ФИО | Telegram | Компания) — источник логинов и компаний.
- Контрагент при создании = компания ответственного из «Контактов» (автоподстановка,
  в т.ч. в предпросмотре — функция enrich_create_command).
- Матчинг имён нечёткий (_person_matches_fio / _surname_match): склонения («Плахотина»),
  инициалы с любой стороны («К. Плахотин», «Плахотин К»), опечатки (Левенштейн ≤ 2).
  Инициал, если указан, обязан совпасть — иначе бот спрашивает логин.
- При создании поручения бот проверяет привязку ответственного к TG-логину;
  если нет — спрашивает админа перед записью (можно «⏭ Пропустить», валидация формата логина).
- Роли: user / admin. Суперадмин упразднён, доступ к бэку только через Kimi Work или консоль.
  Админ может закрывать и править ЛЮБЫЕ поручения (проверка «своё/чужое» — только для user).
- Статус «Новое» упразднён: все поручения через бота создаются со статусом «В работе».
- LLM-режим (кнопка «Редактировать»): свободный текст → канонические команды (мультикоманды),
  предпросмотр с кнопками Да / ✏️ Изменить / Нет («Изменить» — правка фразой, ре-интерпретация
  с учётом исходного запроса), после «Да» — выполнение и выход из режима.
- LLM: kimi-k2.6; temperature не передаём; для перевода команд thinking отключён,
  для совета дайджеста — включён (max_tokens=8000, timeout=120).
- Дайджест: открытые поручения со сроком ≤ 14 дней, сортировка по дате, дни просрочки,
  дата в заголовке; плановый — с советом LLM; кнопка «Дайджест» — выбор чата.
- Удаление предыдущего дайджеста: send_telegram сохраняет message_id в
  `.credentials/last_digest.json` ({chat_id: [ids]}) и удаляет прошлую версию при новой отправке.
  Бот в групповых чатах — участник (не админ): удаляет только свои сообщения и только
  младше 48 часов (пятничный дайджест в понедельник не удалится — известное ограничение).
- Антиповтор кнопки «Дайджест»: флаг `_digest_running` (только пока реально формируется),
  НЕ фиксированные 240 сек.
- Авто-миграция chat_id: при 400 migrate_to_chat_id (группа → супергруппа) бот сам
  переписывает telegram.json (_migrate_chat_id). Чаты рассылки: toolbox = -1004450977548
  (супергруппа!), МТИ&PSI = -1002041861875.
- Переключатель «⏰ Авто-дайджесты» (dg_auto:toggle) гейтит плановые рассылки.
- История изменений реестра — вкладка «Лог» в Google Sheet (дата/время, инициатор, действие, ID, детали).

## BL-28 «Генератор требований к проекту» (@PMO_requirements_bot) — статус: MVP реализовано (06.09.2026)

- Локально: `bl28-requirements-generator/`; сервер: `/opt/bl28-requirements-bot/`,
  сервис `bl28-requirements-bot.service`. Деплой-цикл как у BL-6 (py_compile → scp → restart).
- Пайплайн: исходники (.docx/.txt/.md файлами и текстом в чат) → `generate.py` (kimi) →
  JSON по схеме → `fill_docx` в шаблон `project-requirements-template-v2.docx`
  (генерируется `create_template_v2.py`, структура — `parse_template.py` → template-structure-v2.json).
- Два режима: ⚡ Быстрый — бесплатно, kimi-k2.6, один вызов + thinking, 2–3 мин (~$0.05);
  💎 Pro — kimi-k3, посекционно (6 групп) + проход критика, 10–15 мин (~$0.62);
  бесплатный Pro-прогон: запрос админу → `/grant <uid>`. Usage — `outputs/_usage.jsonl`.
- Себестоимость генерации (цены Moonshot 08.2026: k2.6 $0.95/$4.00, k3 $3.00/$15.00
  за 1M in/out): Быстрый ≈ $0.046 на документ (замер Лензолото: 1.8k in / 11k out,
  6.2k reasoning); в проде подтверждено — среднее по 8 быстрым генерациям ≈ $0.056.
  Pro ≈ $0.62 (7 вызовов, 21k in / 37k out, 17k reasoning) — дороже в ~14 раз.
- Документ полностью на русском: приоритеты «Обязательно / Желательно / Возможно /
  Не входит», нумерация БТ/ФТ/НФТ, незаполненное — [уточнить].
- Название документа модель извлекает из исходников сама (заглушка «Проект» запрещена).
- Открытые вопросы — нумерованным сообщением в чат; ответы пользователя сохраняются
  в сессию (`data/<uid>/answers_NN.txt`, состояние — `data/<uid>/state.json`),
  кнопка «🔄 Перегенерировать с ответами» — без повторного списания Pro-квоты.
- Дневной лимит: 10 генераций на пользователя (первичные + перегенерации вместе),
  счётчик в `config.json` → `daily_gen.<дата МСК>.<uid>` (считается после успешного
  вызова LLM, старые дни чистятся).
- Кнопка «📄 Пустой шаблон» (callback template) — выдача шаблона без лимитов,
  также в ответе на /start. Сообщения короче 25 знаков (MIN_MATERIAL_CHARS) в
  материалы не пишутся (фильтр болтовни; короткие ответы на вопросы — можно).
- Описание бота (Bot API setMyDescription, ≤512 зн.) — `bot-description.txt`;
  инструкция пользователя — `user-guide.md` → `user-guide.docx` (create_user_guide.py);
  релиз-нотс для рассылки — `release-notes-bl28.md`.
- Известная особенность: версия v0.N считается по slug названия, а название может
  меняться между прогонами → нумерация может начаться заново с v0.1.
- Версии: каждый прогон = новый файл `v0.N` + строка в «Истории изменений» документа.
- Rate limit org Moonshot: вызовы последовательно, паузы 4 с, backoff; черновики секций
  в `outputs/_draft_<uid>.json` (resume), CLI-флаги `--sections-only` / `--from-draft`.
- Конфиги на сервере (не в репо!): `.credentials/` — telegram.json (token, owner_id),
  config.json (allowed_user_ids, pro_quota), kimi.json (модели kimi-k2.6 / kimi-k3).

  analytics, diff, llm, report, pdf, xlsx_export, state). Деплой-цикл как у BL-6.
- Рамка фичи и решения — в Notion, страница BL-1. Спека SPEC-PLAN-AUDIT.md — вторична (веб-версия не строим).
- Решения 06.09.26: .mpp в MVP (РЕАЛИЗОВАНО: default-jre-headless + pip jpype1/mpxj,
  JVM внутри процесса бота; маппинг MPXJ → Plan протестирован: связи, длительности,
  baseline, deadline, затраты, ресурсы); маскирования ПДн НЕТ; версии плана — в истории
  Telegram (бот держит только file_id в state.json); PDF без диаграмм D-01…D-04.
- Пайплайн: файл → parse_plan → run_analysis → LLM Kimi k2.6 (thinking ВКЛЮЧЁН,
  max_tokens=16000, timeout=300, ответ ~2,5 мин) → сводка в чат + PDF.
  Качество результата важнее времени и стоимости анализа.
- Вторая пользовательская функция (06.09.26): конвертация .mpp → Excel.
  На .mpp бот отвечает inline-кнопками «Аудит» / «В Excel» (callback_query);
  xlsx_export.py пишет заголовки из COLUMN_SYNONYMS + колонку «Тип»
  (round-trip точный: 632 задачи, 0 расхождений, включая вехи-сводки).
  После конвертации бот предлагает кнопку «Начать аудит» (и наоборот).
- Юнит-экономика (замер 07.09.26 на плане 632 задачи, тарифы api.moonshot.ai
  на 09.2026: $0,95/1M вход, $0,16/1M кэш, $4,00/1M выход; курс ~86 ₽/$):
  аудит ≈ $0,032 (~2,7 ₽) — 12 752 токена, из них thinking 4 507 (56 % затрат);
  худший случай ~$0,081 (~7 ₽). Конвертация ≈ 0 ₽ (без LLM, только CPU).
  Ориентир: 100 аудитов/мес ≈ 275 ₽.
- Аналитика (детерминированно, без LLM): CPM; правила Инструкции R-01…R-12;
  DCMA 14-point (адаптация D-01…D-14: логика, резервы, длительности, валидность дат,
  ресурсы, BEI, тест крит. пути; leads/lags/типы связей/ограничения — из .mpp);
  EVM (PV/EV/SPI, duration-weighted proxy при отсутствии затрат);
  сводный статус on_track / at_risk / off_track (RAG).
- Отчёт по практикам Asana/PMI: инвертированная пирамида, проблемы
  «причина → влияние → действие», рекомендации со сроками и ссылками на R-NN/D-NN.
- UX-редизайн отчёта 10.09.26 (по фидбеку прогона вживую): все метрики
  объясняются простым языком прямо в тексте (SPI → «работы выполняются на 38 %
  от графика»; BEI → «из запланированных к сегодня выполнено 16 %»); строка
  статусов с подписями (Выполнено/В работе/Не начато); раздел DCMA →
  «Качество плана» с легендой «норма ≤ 5 %»; коды R-NN/D-NN и упоминания
  корпоративной Инструкции из вывода УБРАНЫ (правила работают только внутри
  анализа, наружу — человеческие формулировки RULE_TITLES); PDF перестроен под
  «понять за 5 минут»: статус-баннер → «План в цифрах» (колонка «Как читать»)
  → заключение LLM → приложение с детальными таблицами.
- LLM работает только с фактами аналитики — нарушения не выдумывает.
- e2e на реальном плане (План_график_АСУП_техдолг_18_06_26.mpp, 632 задачи):
  парсер → аналитика → LLM → PDF — полный прогон зелёный; пойман и исправлен
  ложноположительный R-07/R-08 по baseline для .mpp.
