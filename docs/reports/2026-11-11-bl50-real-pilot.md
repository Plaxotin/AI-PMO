## Инцидент деплоя (прозрачно)

При копировании `.credentials` в новый релиз файлы получили владельца root с mode 600, сервис не мог их прочитать → webhook отвечал 503 ~9 минут; Telegram прекратил доставку первого сообщения (`pending_update_count=0`), записей не создалось. Права исправлены, пайплайн проверен end-to-end. Первое согласованное сообщение было отправлено повторно — посторонних эффектов у потерянной доставки не было.

## Находки

1. **AI-качество:** срок в естественной формулировке не извлечён (ветка Edit отработала, критерий пилота подтверждён).
2. **UI:** карточка обязательства использует старый рисковый шаблон («Риск · оценка», «Открыть риск»).
3. **UX (требование владельца):** пользовательские сообщения не должны содержать «Исходная версия не изменена» и сырой diff; в обосновании запрещены внутренние ID — нужна ссылка на сообщение-источник либо автор + текст + время получения.
4. **Данные:** `candidate.due` не синхронизирован после Edit (обновлены decision/proposal).
5. **Статус сигнала** остаётся `processing` после завершения контура — уточнить финальные статусы.
6. **Cleanup:** `.env` релиза содержит недостижимый внешний DB-endpoint; реальная БД задаётся systemd drop-in `20-local-db.conf`.
