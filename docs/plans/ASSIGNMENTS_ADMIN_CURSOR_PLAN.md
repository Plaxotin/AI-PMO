## 2. Целевой результат v2.2 (кратко)

Один экран BL-6: smart-input (текст/диктовка/файл) + таблица реестра.
Поток прямой: ввод -> AI-разбор -> строки сразу в таблице в `edit-mode` -> `✓` записывает в Google Sheet, `✗` удаляет черновую строку.

### Фаза BL2-0 — Единый экран + Google Sheets + smart-input + AI-инжест файлов

**phase_id:** BL2-0
**status:** `planned`  
**Зависит от:** —
**Цель:** дать полную MVP-ценность в одной фазе и одном экране, без промежуточных экранов подтверждения.

**Scope:**

- Инициализация и подключение Google Sheet по шаблону (автосоздание + reconnect).
- API для чтения реестра, разбора текста в поля и записи строк в Sheet.
- API инжеста файлов (audio/video) с асинхронным статусом job.
- Единый UI-экран:
  - smart-input (текст + 🎤 + 📎 + ➤),
  - таблица реестра с фильтрами в заголовках,
  - `edit-mode` для новых строк (подсветка, `✓`/`✗`),
  - прогресс обработки файлов.
- STT pipeline: SaluteSpeech + `ffmpeg` (для видео), затем LLM slot-filling и direct-to-table.
- Гарантия non-storage: медиа только во временном контуре, удаление после транскрипции.

**Env (минимум для старта BL2-0):**

- `GOOGLE_SERVICE_ACCOUNT_EMAIL`
- `GOOGLE_PRIVATE_KEY`
- `LLM_API_KEY`
- `SALUTESPEECH_CLIENT_ID`
- `SALUTESPEECH_SECRET`

**Acceptance criteria:**

- Первый вход в BL-6 создаёт/подключает рабочий Sheet и открывает единый экран.
- Текстовый smart-input создаёт строку в `edit-mode`; `✓` сохраняет в Google Sheet.
- Короткий ввод (например, без срока/owner) создаёт строку с частично заполненными полями без ошибки.
- `📎` mp3/mp4 проходит STT+LLM pipeline и создаёт N строк в `edit-mode`.
- `✗` удаляет черновую строку без записи в Sheet.
- Файл > 500 МБ отклоняется валидируемой ошибкой.
- Кнопка «Открыть в Google Sheets» ведёт на активный подключённый реестр.

**testing_scenario:**

| Поле | Значение |
|------|----------|
| **setup** | Подготовлены Google SA, SaluteSpeech и LLM ключи; тестовые mp3/mp4; запущен `npm run dev` в `app/`. |
| **actions** | 1) Открыть BL-6 и проверить автоинициализацию/подключение Sheet. 2) Отправить текст в smart-input и подтвердить `✓`. 3) Отправить минимальный текст и подтвердить `✓`. 4) Загрузить mp3, затем mp4; по итогам принять часть строк `✓`, часть отклонить `✗`. 5) Проверить кейс файла > 500 МБ. 6) Открыть ссылку на Sheet из сайдбара. |
| **expected** | BL-6 работает как one-screen direct-to-table; `✓` создаёт записи в Sheet; `✗` не создаёт; media pipeline работает для аудио/видео; oversized-файл отклоняется. |
| **evidence** | Видео UI-прохода, скриншот таблицы с `edit-mode`, строки в Google Sheet до/после, логи статуса ingest job. |

### Фаза BL2-1 — Telegram-инжест + напоминания (опциональная)

**phase_id:** BL2-1
**status:** `planned_optional`
**Зависит от:** BL2-0
**Цель:** добавить Telegram-канал ввода и базовые напоминания без расширения UI-модели beyond one-screen.

**Scope:**

- Telegram webhook (текст/voice/audio/video), идемпотентная обработка сообщений.
- Pipeline: STT/LLM -> черновые строки -> показ на едином BL-6 экране в `edit-mode`.
- Для файлов > 25 МБ в Telegram: ответ-подсказка перейти к веб-загрузке.
- Напоминания по `Target Date` (cron) с антидублями.

**Env (дополнительно к BL2-0):**

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_WEBHOOK_SECRET`
- `TELEGRAM_REMINDER_CHAT_ID` (или эквивалентный канал назначения)

**Acceptance criteria:**

- Текст в Telegram создаёт строку в `edit-mode` на веб-экране BL-6.
- Voice/video в Telegram проходят STT+LLM и дают N строк в `edit-mode`.
- Повторная доставка того же `message_id` не создаёт дубль.
- Telegram-файл > 25 МБ возвращает корректную подсказку веб-инжеста.
- Напоминание по сроку уходит ровно один раз на интервал.

**testing_scenario:**

| Поле | Значение |
|------|----------|
| **setup** | Рабочий BL2-0; тестовый Telegram bot + webhook; тестовый chat/channel для напоминаний. |
| **actions** | 1) Отправить текст боту. 2) Отправить voice/video. 3) Повторить webhook с тем же `message_id`. 4) Отправить файл > 25 МБ. 5) Подготовить строку с близким `Target Date` и дождаться cron-напоминания. |
| **expected** | Все валидные сообщения превращаются в строки `edit-mode`; дублей нет; oversized-файл получает fallback-инструкцию; напоминание отправляется без повторов. |
| **evidence** | Логи webhook/cron, сообщения в Telegram, скрин BL-6 с incoming `edit-mode` строками, подтверждение записи в Google Sheet. |

## 6. Явные blockers старта по новой спецификации

**Blockers для BL2-0 (критические):**

1. Нет рабочих `GOOGLE_SERVICE_ACCOUNT_EMAIL` / `GOOGLE_PRIVATE_KEY`.
2. Нет валидного LLM API ключа (`LLM_API_KEY`) для slot-filling.
3. Нет SaluteSpeech credentials или отсутствует доступ к STT endpoint.
4. Нет подтверждения прав на автосоздание/запись в целевой Google Sheet.

**Blockers для BL2-1 (опциональная фаза):**

1. Не выдан `TELEGRAM_BOT_TOKEN` и/или webhook secret.
2. Недоступен публичный webhook endpoint.
3. Не определён канал/чат для отправки напоминаний.
