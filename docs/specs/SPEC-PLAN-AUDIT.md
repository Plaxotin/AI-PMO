## 1. Обзор продукта

Пользователь загружает файл плана проекта (Excel, CSV, MS Project), выбирает режим анализа и через 30–90 секунд получает готовый отчёт: ошибки, зависимости, критический путь, прогресс, рекомендации, **проверку соответствия корпоративной Инструкции и диаграммы по её шаблонам**.

Никакой регистрации, базы данных или интеграций — «загрузил → получил результат».

**Ключевые принципы:**
- Zero setup; один вход — один файл: `.xlsx`, `.xls`, `.csv`, `.mpp`, `.xml` (MSPDI)
- Мгновенная ценность — результат за < 90 секунд (< 150 сек для mpp)
- AI-дифференциатор — анализ, который PM не сделает вручную за разумное время
- **Соответствие стандарту** — проверка по Инструкции с рекомендациями и ссылками на пункты (новое v0.2.2)
- Privacy by design — ПДн не уходят во внешний LLM в немаскированном виде (§5.5)
- Freemium: 3 анализа/день бесплатно

## 2. Пользовательские сценарии

US-1…US-6 без изменений. Дополнение v0.2.2:

**US-7: Проверка по Инструкции (новое v0.2.2)**

Без изменений: Полный аудит / Критический путь / Ошибки и конфликты / Сводка. Во всех режимах блок «Соответствие Инструкции» включён в «Полный аудит» и «Ошибки и конфликты».

### 4.2 Структура данных
Базовый набор v0.1 + дополнения из mpp/xml (WBS, типы связей + лаги, календари, baseline, стоимости, ресурсы). **Для проверки по Инструкции дополнительно извлекаются (если есть):** крайний срок вехи (deadline), Затраты, БСЗР, БСВР, ОКП, ООКП, Свободный временной резерв, Режим задачи (авто/ручной), поле «Ключевой результат». Отсутствие поля — само по себе нарушение (R-06/R-08).

### 4.3–4.5 Без изменений
Авто-маппинг колонок; лимиты (mpp до 15/50 MB); реестр ПДн-полей (Ответственный/Ресурс/Resource Names маскируются).

## 5. AI-пайплайн обработки

| СТАДИЯ | ЧТО | ВРЕМЯ | ГДЕ |
|---|---|---|---|
| 1. Парсинг/Конвертация | файл → JSON задач | 1–3 сек / 5–30 сек (mpp) | Клиент / Конвертер |
| 2. Валидация | обяз. поля, даты, дубликаты | < 1 сек | Клиент |
| 3. Деидентификация | ФИО → токены P-### | < 1 сек | Клиент / Конвертер (mpp) |
| 4. Анализ | алгоритм (CPM) + **движок правил Инструкции** + LLM | 20–60 сек | Сервер |
| 5. Рендер + реидентификация | отчёт + диаграммы + PDF | 2–5 сек | Клиент |

### 5.1 Алгоритмическая часть
Без изменений (DAG, CPM, float — резерв ≤ 5 дней = критическая задача, см. R-03).

### 5.2–5.3 Промпт и JSON-контракт
Контракт дополняется массивом `compliance` (см. §5.6) и блоком `instruction_refs`. LLM (Kimi) получает результаты движка правил и формулирует рекомендации человеческим языком, **не выдумывая нарушения**: только интерпретация найденных движком фактов.

### 5.4 LLM-контур (обновлено v0.2.2)

| | |
|---|---|
| **Beta (текущая)** | **Kimi (Moonshot AI)** — единственный провайдер. API: OpenAI-совместимый endpoint `api.moonshot.cn`, модель семейства kimi-k2 / moonshot-v1-128k (контекст ≥ 128k — большие планы до 5000 строк помещаются целиком) |
| **Абстракция** | `lib/llm.ts`: единая точка; провайдер и модель через env (`LLM_PROVIDER=kimi`, `LLM_MODEL=...`) |
| **ПДн** | Маскирование до LLM (§5.5) — ст. 12 152-ФЗ не применяется |
| **Enterprise** | Опция RU-контура (GigaChat/YandexGPT) или on-prem — переключением env, без смены кода |
| **Fallback** | При недоступности/лимите Kimi — очередь + retry с backoff; сообщение пользователю (другого провайдера в beta нет) |

### 5.5 Модуль деидентификации
Без изменений (v0.2/v0.2.1): клиентский режим (xlsx/csv/xml) и конвертерный (mpp). Гарантия: немаскированные ПДн не уходят в Kimi и не персистируются.

### 5.6 Модуль соответствия Инструкции (новое v0.2.2)

Проверяет план по правилам `Инструкция_Project_Plan.docx` (корпоративный стандарт ведения плана в MS Project). Работает **детерминированно (не LLM)**, поверх JSON задач; результат — массив нарушений с evidence и ссылкой на пункт Инструкции. LLM только формулирует рекомендации.

| ID | ПРАВИЛО (пункт Инструкции) | ПРОВЕРКА | SEVERITY |
|---|---|---|---|
| R-01 | Всем задачам, кроме первой/последней и ключевых вех, назначены предшественники и последователи; нет «подвисших» задач (п. 1) | У листовой задачи пусты оба поля связей | High |
| R-02 | Суммарные задачи не имеют предшественников/последователей (п. 1) | У summary есть связи | High |
| R-03 | Критические задачи = резерв ≤ 5 дней (п. 1) | Из CPM: float > 5 дней у задач на крит. пути — флаг | Info |
| R-04 | Контрольным вехам УК: крайний срок (deadline) + длительность 0 (п. 1) | Веха без deadline или dur ≠ 0 | High |
| R-05 | Этапы с вехами вынесены в отдельный раздел, названия совпадают с протоколами УК (п. 1) | Нет раздела «Ключевые вехи»/несовпадение имён этапов и вех | Medium |
| R-06 | «Затраты» суммарно = 100 ₽, декомпозированы до ключевых работ (п. 1) | Колонка Затраты отсутствует / сумма ≠ 100 / не заполнена у листьев | Medium |
| R-07 | Базовый план сохранён; обновляется только по суммарным задачам и ЗнИ (п. 1) | Задачи/этапы без baseline-полей | High |
| R-08 | Рекомендованный состав колонок: Режим задачи (авто), БСЗР, БСВР, ОКП, ООКП, Свободный резерв, «Ключевой результат» (п. 1) | Отсутствующие колонки — списком | Medium |
| R-09 | Сроки «в прошлом» отсутствуют (разд. 4–5) | Окончание < даты отчёта и % < 100 | High |
| R-10 | Неначатые по графику задачи актуализированы (разд. 4) | Начало < даты отчёта и % = 0 | Medium |
| R-11 | Базовые сроки/затраты/длительность не изменены вручную (разд. 5) | Отклонение текущих дат от baseline без признака ЗнИ, порог > 30 дней | Medium |
| R-12 | Даты окончания = базовым датам окончания или отклонение зафиксировано (разд. 4) | Отклонение окончания от baseline по задаче | Info |

**Формат результата:**
```json
"compliance": [
  {"rule": "R-01", "severity": "high", "count": 129,
   "evidence": ["разработка ПО", "Тестовая эксплуатация", "..."],
   "instruction_ref": "п. 1: «Всем задачам… присвоить предшественников и последователей»",
   "recommendation": "Назначьте связи FS 129 задачам; начните с задач критического пути"}
]
```
Сводный индекс соответствия: `compliance_score = 100 − Σ(вес severity × count_norm)` — выводится в шапку отчёта.

## 6. Спецификация выходных данных

### 6.1 Интерактивный отчёт — секции (обновлено v0.2.2)

| СЕКЦИЯ | СОДЕРЖИМОЕ | ВИЗУАЛИЗАЦИЯ |
|---|---|---|
| Оценка плана | Балл 1–10 + 5 критериев + **compliance_score** | Gauge + radar |
| **Соответствие Инструкции** | Чек-лист R-01…R-12 с ✓/✗, количеством нарушений, evidence, ссылками на пункты | Таблица-чеклист |
| Критический путь | Цепочка задач + длительность | Timeline |

| **D-03 Ключевые работы проекта** | Линейчатая с группировкой по уровню структуры: Затраты/БСЗР/БСВР или %-proxy (как разд. 3 Инструкции) | Grouped bar |
| **D-04 Таблица ключевых работ** | СДР, название, окончание, % завершения, БСЗР, БСВР, Затраты, ООКП, комментарий; цветовая шкала ООКП зелёный→красный (как разд. 3 Инструкции) | Таблица |
| Ошибки | Severity, описание, предложение, evidence | Карточки |
| Сводка | KPI: задач, вех, %, дней, ресурсов | Stat-карточки |
| Рекомендации | Советы с привязкой к пунктам Инструкции | Нумерованный список |

| ID | КРИТЕРИЙ |

## 13. Риски и митигация

| РИСК | ВЕРОЯТН. | МИТИГАЦИЯ |

| Недоступность/лимиты Kimi API | Средняя | Retry + backoff, очередь, кэш результатов парсинга; мониторинг лимитов |
