## 0. Обоснование пивота (v1.3 → v2.0)

### Проблемы v1.3

| Проблема | Влияние |
|----------|---------|
| Полностью кастомный UI реестра (список, карточка, формы, фильтры) | Большой объём фронтенд-разработки, UX хуже привычных таблиц |
| Postgres + Supabase как хранилище реестра | Инфраструктурная сложность, миграции, auth |
| Публичный реестр на Yandex Object Storage + CDN | Отдельная генерация статики, деплой, cache invalidation |
| 6 фаз (BL1-0 … BL1-5), ~76–197 USD API-эквивалента | Долгий путь до ценности; пользователь не видит результат после BL1-0 |
| Импорт/экспорт CSV/XLSX, signed links | Реимплементация того, что Google Sheets уже умеет |

### Решение v2.0

**Google Sheets — единственный реестр поручений.** Инструмент BL-6 не дублирует табличный UI, а добавляет поверх Google Sheets то, что таблица не умеет сама: **AI-извлечение поручений из записей совещаний** (аудио/видео → STT → LLM → структурированные строки).

**Результат:** 3 компактные фазы вместо 6, первая ценность после фазы BL2-0 (ручной ввод + Google Sheets), убийственный сценарий — после BL2-1.

## 1. Цель и результат

Инструмент BL-6 **заполняет реестр поручений** в Google Sheets **по стандартному шаблону PMI Action Item Tracker** с минимальным усилием пользователя.

**Два режима работы:**

1. **Ручной ввод** — форма в веб-интерфейсе AI PMO → поручение появляется в Google Sheet.
2. **AI-инжест** — загрузка аудио/видеозаписи совещания (веб или Telegram) → STT + LLM → список извлечённых поручений → пользователь подтверждает/редактирует → подтверждённые строки автоматически попадают в Google Sheet.

**Убийственный сценарий:** пользователь загружает запись летучки → через минуту в привычной Google-таблице появляются готовые строки поручений с заполненными полями Brief Name, Description, Source, Owner, Priority, Target Date.

**Ключевое отличие от v1.3:** инструмент **не заменяет** Google Sheets кастомным UI. Таблица остаётся единственным местом для просмотра, редактирования, совместной работы и экспорта. AI PMO — это «ворота», через которые данные попадают в таблицу.

## 5. Объём MVP (v2.0)

### 5.1 Обязательно в MVP

1. **Подключение Google Sheet:** пользователь указывает URL таблицы (шаблон PMI); приложение проверяет доступ и структуру колонок.
2. **Встроенный вид реестра:** read-only таблица в интерфейсе AI PMO, отображающая текущее содержимое Google Sheet + прямая ссылка «Открыть в Google Sheets» для редактирования.
3. **Ручной ввод:** форма в AI PMO с полями шаблона → запись добавляется в Google Sheet через Sheets API.
4. **AI-инжест (веб-загрузка):** аудио/видео → SaluteSpeech STT → LLM extraction → экран подтверждения → batch-запись подтверждённых строк в Google Sheet.
5. **Экран подтверждения:** таблица извлечённых поручений; пользователь может отредактировать каждое поле, удалить строку, добавить строку вручную; кнопка «Записать в реестр».
6. **Telegram-инжест:** аудио/видео/текст боту → тот же pipeline → черновики через API → пользователь подтверждает в веб-UI → запись в Sheet.

### 5.2 Вне MVP (бэклог)

- Напоминания в Telegram по `Target Date` (читать из Sheet → cron → уведомление).
- Автоматический мониторинг просроченных поручений.
- Интеграция с Notion, Jira, Trello.
- Мультитаблица (несколько Sheet на проект).
- Мобильное приложение / PWA.
- Двусторонняя синхронизация (изменения в Sheet → обновления в AI PMO).
- SSO / корпоративный LDAP.

### 5.3 Вне MVP (явно не входит)

- Полный кастомный UI реестра с CRUD (решение v1.3 — отменено).
- Публичный CDN-реестр (Google Sheets sharing достаточен).
- Собственная БД для поручений.

## 6. Функциональные требования

### 6.1 Подключение Google Sheet

- При первом запуске инструмента BL-6 пользователь вводит URL Google Sheet.
- Приложение проверяет:
  - Доступ (Service Account или OAuth) к таблице.
  - Наличие заголовочной строки с ожидаемыми колонками (A–K по шаблону).
- При несоответствии — понятное сообщение об ошибке с инструкцией.
- URL Sheet сохраняется в конфигурации проекта (localStorage или env).

### 6.2 Встроенный вид реестра

- Таблица в интерфейсе AI PMO, отображающая актуальные данные из Google Sheet (через Sheets API `spreadsheets.values.get`).
- Обновление при открытии страницы + кнопка «Обновить».
- Сортировка и фильтрация на клиенте (по Status, Priority, Owner, Target Date).
- Прямая ссылка «Открыть в Google Sheets» — открывает оригинал в новой вкладке.
- **Никаких операций записи из этого вида** — редактирование только через Google Sheets или форму ввода AI PMO.

### 6.3 Ручной ввод

- Форма с полями: Brief Name, Description, Source, Owner, Priority, Target Date.
- `ID` — автоматически (max(ID) + 1 из Sheet).
- `Date Added` — текущая дата.
- `Status` — «1-Not started» по умолчанию.
- `Running Status Comments`, `Completion Date` — пустые.
- Валидация: Brief Name обязательно; Target Date — формат даты; Priority — 1/2/3.
- После submit → `spreadsheets.values.append` → новая строка в Sheet → обновление встроенного вида.

### 6.4 AI-инжест (веб-загрузка)

**Ввод:**

- Форма загрузки: файл (аудио: `.mp3`, `.m4a`, `.ogg`, `.wav`, `.opus`; видео: `.mp4`, `.mov`, `.webm`, `.mkv`), ≤ 500 МБ.
- Опциональные поля контекста: название мероприятия (`Source`), дата, список участников.

**Pipeline:**

1. Загрузка файла → tmp.
2. Видео → ffmpeg → аудиодорожка; аудио — напрямую.
3. SaluteSpeech STT → транскрипт.
4. Удалить медиафайл немедленно.
5. LLM: разбить транскрипт на отдельные поручения; для каждого извлечь: `Brief Name`, `Description`, `Owner`, `Priority`, `Target Date`.
6. `Source` — из поля контекста или автоматически (формат: «Совещание <название>, <дата>»).
7. Показать **экран подтверждения**.

**Экран подтверждения:**

- Таблица извлечённых поручений (одна строка = одно поручение).
- Все поля редактируемы inline.
- Можно удалить строку (отклонить поручение).
- Можно добавить строку вручную.
- Кнопка «Записать в реестр» → batch `spreadsheets.values.append` → строки появляются в Google Sheet.
- Кнопка «Отмена» → ничего не записывается.

**Обработка ошибок:**

| Ситуация | Реакция |
|----------|---------|
| Файл > 500 МБ | Отказ до загрузки с подсказкой |
| Неподдерживаемый формат | Отказ с перечнем допустимых |
| SaluteSpeech недоступен | Сообщение «STT-сервис недоступен, попробуйте позже»; задание сохраняется для retry |
| Google Sheets API ошибка | Сообщение с деталями; retry |
| LLM не извлёк поручения | Сообщение «Не удалось извлечь поручения из записи»; предложение ручного ввода |

### 6.5 Telegram-инжест

- Telegram-бот принимает: текст, голос, аудио, видео.
- **Текст** → LLM extraction → 1 поручение.
- **Голос/аудио/видео** → SaluteSpeech STT → LLM → поручение(я).
- Эвристика US-C (запись совещания): ключевые слова, duration ≥ 90 с, файл ≥ 3 МБ → множественное извлечение.
- Результат: бот отвечает в тред: «Извлечено N поручений — подтвердите в веб-интерфейсе: <ссылка>».
- Подтверждение — через тот же экран подтверждения (§6.4) → запись в Google Sheet.
- Файлы из Telegram > 25 МБ → подсказка использовать веб-загрузку.

### 6.6 Данные и конфиденциальность

Без изменений по сравнению с v1.3 §7:
- В LLM — только нормализованный транскрипт + контекст мероприятия.
- Медиафайлы не хранятся.
- Google Sheet — ответственность пользователя за sharing и PII.

## 8. Контракт API (логический, MVP)

### Конфигурация Sheet

```
POST /api/projects/:projectId/sheets/connect
     Body: { spreadsheet_url: string }
     → { ok: true, sheet_title: string, row_count: number }

GET  /api/projects/:projectId/sheets/status
     → { connected: boolean, spreadsheet_url?, last_synced_at? }
```

### Реестр (read-only из Sheet)

```
GET  /api/projects/:projectId/assignments
     → { data: Row[], meta: { total: number, spreadsheet_url: string } }
```

### Ручной ввод

```
POST /api/projects/:projectId/assignments
     Body: { brief_name, description?, source?, owner?, priority?, target_date? }
     → { ok: true, row_number: number }
```

### AI-инжест (веб-загрузка)

```
POST /api/projects/:projectId/ingest
     Content-Type: multipart/form-data
     Fields:
       file           — аудио/видео, ≤ 500 МБ
       meeting_title  — (опц.)
       meeting_date   — (опц.)
       participants   — (опц.) JSON-массив

GET  /api/projects/:projectId/ingest/:jobId
     → { status: pending|processing|done|failed, drafts?: Draft[] }

POST /api/projects/:projectId/ingest/:jobId/confirm
     Body: { rows: Row[] }
     → { ok: true, rows_written: number }
```

### Telegram Webhook

```
POST /api/telegram/webhook
```

### Фаза BL2-0 — Google Sheets интеграция + ручной ввод + встроенный вид

**phase_id:** BL2-0  
**status:** `planned`  
**Зависит от:** —

**Цель:** пользователь подключает Google Sheet, видит реестр в AI PMO, добавляет поручения через форму.

**Scope:**

- Google Sheets API: авторизация (Service Account или OAuth 2.0), чтение, запись.
- Endpoint `/api/projects/:projectId/sheets/connect` — валидация URL, проверка структуры колонок.
- Endpoint `GET /api/projects/:projectId/assignments` — чтение строк из Sheet.
- Endpoint `POST /api/projects/:projectId/assignments` — добавление строки.
- Web UI: страница инструмента BL-6:
  - Блок «Подключить таблицу» (ввод URL, статус подключения).
  - Встроенная таблица реестра (данные из Sheet, клиентские фильтры/сортировка).
  - Кнопка «Открыть в Google Sheets» (внешняя ссылка).
  - Форма ручного ввода поручения.
- Конфигурация проекта: хранение `spreadsheet_id` (env или БД — минимально).

**Env:** `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY` (или `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET` для OAuth).

**Критерий готовности:**

- Google Sheet подключена; данные отображаются в AI PMO.
- Форма ручного ввода → строка появляется в Google Sheet.
- Ссылка «Открыть в Google Sheets» работает.
- Фильтрация по статусу, приоритету.

**testing_scenario:**

| Поле | Значение |
|------|----------|
| **setup** | Google Sheet по шаблону PMI с 3–5 тестовыми строками; Service Account с доступом; `npm run dev`. |
| **actions** | 1) Подключить Sheet по URL. 2) Проверить отображение строк. 3) Заполнить форму → submit. 4) Открыть Google Sheet → проверить новую строку. 5) Изменить строку в Google Sheets → обновить вид в AI PMO. |
| **expected** | Строки отображаются; новая строка записана в Sheet; изменения видны после обновления. |
| **evidence** | Скриншот/видео UI; содержимое Google Sheet до и после. |

### Фаза BL2-1 — AI-инжест (веб-загрузка) + экран подтверждения

**phase_id:** BL2-1  
**status:** `planned`  
**Зависит от:** BL2-0

**Цель:** убийственный сценарий — загрузка записи совещания → AI извлекает поручения → пользователь подтверждает → строки в Google Sheet.

**Scope:**

- Endpoint `POST /api/projects/:projectId/ingest` — приём файла, STT, LLM extraction.
- Endpoint `GET .../ingest/:jobId` — статус и черновики.
- Endpoint `POST .../ingest/:jobId/confirm` — batch-запись в Google Sheet.
- STT pipeline: SaluteSpeech (или Whisper fallback); ffmpeg для видео.
- LLM prompt: извлечь из транскрипта список поручений с полями Brief Name, Description, Owner, Priority, Target Date.
- Web UI: экран подтверждения (таблица черновиков, inline-редактирование, удаление строк, ручное добавление, кнопки «Записать» / «Отмена»).
- Прогресс-бар / статус обработки (polling).
- Медиафайл удаляется сразу после STT.

**Env (дополнительно):** `SALUTESPEECH_CLIENT_ID`, `SALUTESPEECH_SECRET`.

**Критерий готовности:**

- Загрузка mp3 → транскрипция → извлечение → экран подтверждения → confirm → строки в Google Sheet.
- Загрузка mp4 → ffmpeg → тот же pipeline.
- Файл удалён с сервера после STT.
- Файл > 500 МБ → отказ.
- LLM не извлёк → сообщение + возможность ручного ввода.

**testing_scenario:**

| Поле | Значение |
|------|----------|
| **setup** | BL2-0 завершена; тестовые mp3/mp4 (короткое совещание); SaluteSpeech credentials; Google Sheet подключена. |
| **actions** | 1) Upload mp3 → дождаться extraction → review → confirm. 2) Upload mp4 > 25 МБ → async processing → confirm. 3) Upload > 500 МБ. 4) Mock SaluteSpeech failure. 5) Проверить tmp через 60 с. |
| **expected** | Строки в Google Sheet после confirm; async для больших файлов; 413 для > 500 МБ; graceful error для STT; tmp пуст. |
| **evidence** | Скриншот/видео экрана подтверждения; Google Sheet с новыми строками; ls tmp. |

### Фаза BL2-2 — Telegram-инжест + напоминания (опциональная)

**phase_id:** BL2-2  
**status:** `planned`  
**Зависит от:** BL2-1

**Цель:** альтернативный канал ввода через Telegram; базовые напоминания по `Target Date`.

**Scope:**

- Telegram Bot webhook: приём текста, голоса, аудио, видео.
- Эвристика US-C vs одиночное поручение (как в v1.3).
- Pipeline: STT → LLM → drafts → ответ в тред со ссылкой на веб-подтверждение.
- После confirm в веб-UI → запись в Google Sheet (reuse BL2-1).
- Напоминания: cron читает `Target Date` из Sheet → отправляет в Telegram за N дней до дедлайна.
- Антидубли напоминаний (в памяти или простой Sheet «Reminder Log»).

**Env (дополнительно):** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`.

**Критерий готовности:**

- Текст боту → поручение (после подтверждения) в Google Sheet.
- Аудио → STT → поручение.
- Запись совещания → список черновиков → подтверждение → строки в Sheet.
- Напоминание за N дней до дедлайна → сообщение в канал.

**testing_scenario:**

| Поле | Значение |
|------|----------|
| **setup** | Telegram test bot; BL2-1 pipeline; Google Sheet. |
| **actions** | Текст; voice; видео; файл > 25 МБ; повтор webhook; поручение с Target Date через 1 ч. |
| **expected** | Корректные drafts → confirm → Sheet; > 25 МБ → подсказка; идемпотентность; напоминание. |
| **evidence** | Telegram-сообщения; Google Sheet; reminder log. |

## 10. Последовательность и зависимости

```
BL2-0 (Sheets + ручной ввод + встроенный вид)
  └─► BL2-1 (AI-инжест + экран подтверждения) ← УБИЙСТВЕННЫЙ СЦЕНАРИЙ
        └─► BL2-2 (Telegram + напоминания) — опциональная
```

**Первая ценность (BL2-0):** пользователь видит реестр и заполняет его через форму — быстрее, чем открывать Sheet вручную.

**Ключевая ценность (BL2-1):** AI-инжест записей совещаний — то, ради чего существует инструмент.

**Расширение (BL2-2):** Telegram-канал и напоминания — удобство для команд, уже использующих Telegram.

## 12. Альтернативы (рассмотрены и отклонены)

| Вариант | Плюсы | Минусы | Решение |
|---------|-------|--------|---------|
| **iframe Google Sheets** в интерфейсе | Нулевая разработка отображения | Google блокирует iframe с full editor (X-Frame-Options); edit-mode недоступен; read-only publish view — визуально бедный | **Отклонён:** ненадёжно, плохой UX |
| **Google Sheets как iframe (publish view) + API для записи** | Гибрид: отображение через iframe, запись через API | Publish view — медленный, без фильтров; десинхрон между iframe и API | **Отклонён:** хуже, чем чистый API-подход |
| **Google Sheets Add-on (sidebar)** | Пользователь остаётся полностью в Google Sheets | Сильные ограничения на upload файлов; сложный UX для аудио/видео; нет Telegram-интеграции | **Отклонён для MVP;** возможен как дополнение позже |
| **Airtable / Notion как backend** | Более богатый API, чем Sheets | Меньше распространены; не совместимы с PMI-шаблоном; vendor lock-in | **Отклонён:** Google Sheets — стандарт для PMI |
| **Custom DB + table UI (v1.3)** | Полный контроль | UX хуже привычных таблиц; огромный объём работы; уже показал неудобный интерфейс | **Отклонён (текущий пивот)** |
| **✅ Google Sheets API (read + write) + thin web UI** | Привычный редактор; минимум кастомного UI; быстрый TTV | Зависимость от Google API; rate limits | **Выбран** |

## 13. Технологический стек (v2.0)

- **Приложение:** Next.js (App Router), React, TypeScript — каталог `app/`.
